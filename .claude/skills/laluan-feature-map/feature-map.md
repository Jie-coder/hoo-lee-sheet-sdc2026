# Laluan feature map

Hand-written. `npm run feature-map:check` fails if a route in `src/app` has no
`### Route:` heading here, or if a `data-testid` in the code is not mentioned
in backticks. Machine-found facts: `routes.generated.json` (every interactive
element with label, kind, section, "shown when", "disabled when", where it
navigates; redirect guards; API calls; data sources).

Pictures (all generated by `npm run feature-map:render`, PNG at 2x + SVG):

- `feature-map.png` / `.svg`: overview. One box per page with its test-id
  elements, the main journey in thick orange, decisions, and the
  "Data sources & API routes" box.
- `pages/<page>.png` / `.svg`: one detail diagram per page (`home`, `profile`,
  `interview`, `results`, `pathway`, `radar`, `status`, `demo`, `header`) with
  every control grouped by section, the redirect guards as red diamonds, and
  the data each page reads.

How to read them: dark pill = page entry; orange box = main journey element;
blue box = element with a `data-testid`; grey box = element without one;
red diamond = redirect guard found in the code; yellow diamond = decision
from `scripts/feature-map/annotations.ts`; teal hexagon = API route;
cylinders = data (green Supabase table, amber curated CSV catalogue, indigo
sessionStorage); purple = AI provider (Gemini); dashed grey = mock data;
flag shape = outcome or side effect (toast, stays on page).

User journey: `/` -> `/profile` -> `/interview` -> `/results` -> `/pathway`.
Side pages: `/radar`, `/status`, `/demo`.

Flow state (consent, profile, interview answers, chosen role) lives in
sessionStorage via `FlowProvider` (`src/context/flow-context.tsx`); it is
cleared when the tab closes or by `pathway-delete-data`.

Where data comes from:

| Source | Used by | Notes |
| --- | --- | --- |
| Curated catalogue `src/data/catalogue.json` (built from `data/*.csv`) | `/` preview, `/radar`, `/pathway`, `POST /api/roles` | No LLM, no secrets; same input gives same output |
| Mock personas + sample CV PDFs (`src/mocks/personas`) | `/profile`, `POST /api/roles` | Synthetic only |
| `POST /api/roles` | `/results`, `/pathway` (cached per tab by `src/lib/use-roles.ts`) | Error -> "Try again" |
| `POST /api/analyze` | `/demo` | `AI_MOCK=true` -> mock fixture, else Gemini via AI SDK `generateText` |
| `GET/POST /api/items` | `/demo` "Save result" | Supabase table `items`; 500 when Supabase env is missing |
| Health checks (`src/lib/health.ts`) | `/status`, `GET /api/health` | Env vars, Supabase `items`, AI provider (skipped in mock mode) |

## Global: site header (every page)

Detail picture: `pages/header.png`.
- Logo link `header-home` (aria-label "Laluan home") -> goes to `/`.
- Progress stepper (Profile, Interview, Results, Pathway) is display-only on flow pages
  (desktop: stations on one line; mobile: "2/4 Interview" text).
- Course language group (role group, aria-label "Course language"): toggle buttons
  EN / BM / 中文 (aria-pressed; default BM).

### Route: `/`

Landing page (`src/components/landing-view.tsx`). Detail picture: `pages/home.png`.
- Reach: open `/`.
- Sections: Hero (Start, consent), preview route (real result for Aisyah, from the catalogue),
  "Four stops" strip (display only).
- Elements:
  - `landing-consent` (role checkbox): tick "I understand Laluan uses synthetic CVs...".
    Sets `consent` in flow state.
  - `landing-start` (button "Start").
- Decision on Start: consent ticked? yes -> `/profile`; no -> stays on `/`,
  consent label shakes and gets focus (flow `consent-guard`).
- Data: catalogue (preview), flow state.

### Route: `/profile`

Pick a sample CV or upload one (`src/components/profile-view.tsx`). Detail picture: `pages/profile.png`.
- Reach: `/` -> tick `landing-consent` -> `landing-start`.
- Guard: consent not ticked -> redirect to `/`.
- Sections and elements:
  - PersonaCard: `persona-card-*` (role radio), ids: `persona-card-aisyah`, `persona-card-lim-jia-hui`, `persona-card-pravin`.
    Keyboard: Enter or Space selects a focused card. "View CV" link opens the PDF in a new tab.
    Choosing fills the profile from the mock persona and opens the details panel.
  - Upload: `profile-upload-browse` (button "browse"): opens file picker (synthetic PDF, max 2 MB); drag-and-drop also works.
    Mock parse -> toast "Mock parse complete" -> editable empty profile.
  - After a CV is chosen ("Parsed profile" panel): "Your name" input; skills chips with
    "Remove <skill>" buttons, "Add a skill" (then "Skill name" input: Enter adds, Escape cancels);
    roles ("Role title" + years inputs, "Remove <role>", "Add a role"); education
    ("Qualification", "Institution", "Remove education entry", "Add education");
    course language chips EN / BM / 中文 (multi-select).
  - `profile-continue` (button "Continue").
- Expected: details panel appears after choosing a CV; Continue -> `/interview`.
- Data: mock personas, flow state.

### Route: `/interview`

Five quick questions (`src/components/interview-view.tsx`). Detail picture: `pages/interview.png`.
- Reach: full journey to `/profile`, choose a persona, `profile-continue`.
- Guards: consent not ticked -> `/`; no CV chosen -> `/profile`.
- Questions (one at a time, answer chips are aria-pressed toggles):
  - Q1: Hours a week (4 / 6 / 10 / 15 h), Budget for courses (Free only / Up to RM200 / Up to RM500 / No limit).
  - Q2: task shares per CV task (~10% / ~25% / ~40% / 50%+), "Split evenly".
  - Q3: tools text input (placeholder "Excel, WhatsApp Business, Canva"), "How much have you used AI tools?".
  - Q4: Work status, Registered with PERKESO? (Yes / No / Not sure).
  - Q5: A cause you care about, Course language for your pathway (EN / BM / 中文).
- Question navigation: `interview-back` ("Back", disabled on question 1), `interview-skip` ("Skip"),
  `interview-next` ("Next"; on question 5 it reads "See results").
- Expected: after the 5th `interview-next` (or Skip on Q5) answers are saved -> `/results`.

### Route: `/results`

Ranked roles for the profile, from `POST /api/roles` (curated data, no secrets). Detail picture: `pages/results.png`.
- Reach: finish `/interview`.
- Guards: consent not ticked -> `/`; no CV chosen -> `/profile`.
- On load: `POST /api/roles` (cached per tab). Error -> error panel with `results-retry`;
  ok -> scenario tabs and ranked role cards.
- Elements:
  - `scenario-tab-*` (role tab): `scenario-tab-co` Co-Pilot Economy, `scenario-tab-dis`
    Age of Displacement, `scenario-tab-sup` Supercharged Progress.
    Keyboard: ArrowLeft/ArrowRight/ArrowUp/ArrowDown move between tabs, Home/End jump to first/last.
  - Trend signal date toggle (role group "Trend signal date"): latest vs 30 days earlier
    (disabled when there is no earlier snapshot).
  - Per role card: `role-choose` ("Choose this role" / "Chosen"), "Flag this" on inferred links
    (toast "Flagged target ... for a person to review"), SDG badge "Flag this", "Show N sources"
    disclosure with source chips (links).
  - `results-radar-link` -> `/radar` (shown when a prior snapshot exists).
  - `results-retry` ("Try again", only shown when the API call fails).
- Expected: ranking reorders per scenario; `role-choose` -> `/pathway?role=<occupationId>`.

### Route: `/pathway`

Week-by-week plan for the chosen role (`src/components/pathway-view.tsx`). Detail picture: `pages/pathway.png`.
- Reach: on `/results`, click a `role-choose`.
- Guards: consent not ticked -> `/`; no CV chosen -> `/profile`; no `?role=` -> `/results`.
- On load: `POST /api/roles` (same cache as results). Loading -> "Building your plan…";
  error -> panel + "Try again"; role not in results -> panel + "Back to roles" (-> `/results`).
- Elements: course "Open source" links (open provider site), `pathway-back-to-roles` (-> `/results`),
  `pathway-download` ("Download PDF": shows a toast that download is not available in the demo),
  `pathway-delete-data` ("Delete my data": clears flow state, -> `/`), SDG "Flag this", source chips.
- Expected: heading "Your N-week route to <role>".
- Data: catalogue (courses, programmes, skill groups), `/api/roles`, flow state.

### Route: `/radar`

Future Skills Radar, rising/declining skills from arXiv keyword counts (`src/components/radar-view.tsx`).
Detail picture: `pages/radar.png`.
- Reach: open `/radar`, or `results-radar-link` on `/results`.
- Elements: trend signal date toggle, keyword links (arXiv), info popovers,
  `radar-match-skills` ("Match your own skills" -> `/`).
- Expected: rising and declining lists render from `data/keywords*.csv` (catalogue).

### Route: `/status`

Integration health checks (`src/app/status/page.tsx`). Detail picture: `pages/status.png`.
- Reach: open `/status` (not linked from the UI).
- No interactive elements. Checks: environment variables, Supabase (`items` table),
  AI provider (skipped when `AI_MOCK=true`; live call only via `/api/health?deep=1`).
- Expected: one card per integration, badge "OK" or "Error". Needs `.env` secrets for OK.

### Route: `/demo`

Starter demo of `/api/analyze` (`src/app/demo/page.tsx`). Detail picture: `pages/demo.png`.
- Reach: open `/demo` (not linked from the UI).
- Elements: `demo-input` (textarea), `demo-load-example` (fills sample text; disabled while loading),
  `demo-submit` (disabled while loading or with empty input; POSTs `/api/analyze`),
  `demo-save` (shown after a result; POSTs to `/api/items`, needs Supabase).
- `/api/analyze`: `AI_MOCK=true` -> mock fixture, else Gemini. `/api/items`: Supabase env missing -> 500 -> error toast.
- Expected: result cards; "Mock mode" badge when `AI_MOCK=true`.

## Keeping the map current

- Scanner: `scripts/feature-map/scan.ts` (TypeScript parser; elements, labels, guards, fetch calls).
- Hand-written facts: `scripts/feature-map/annotations.ts` (journey, action labels, decisions
  inside handlers, data-source detectors, human names for conditions). `--check` fails if they
  point at a test id, route, component or data source that no longer exists, if a click decision
  misses one of the click's real destinations, or if a redirect guard has no human label.
